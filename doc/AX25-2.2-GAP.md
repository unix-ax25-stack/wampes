# AX.25 2.2: the gaps, and the plan to close them

What WAMPES still did not speak of the 2.2 level-protocol, how each gap
was closed, and what has been closed already - every gap in the table is
shipped.  The one decision with real consequences (what a wire answer
means to a peer that has not proven itself) is marked *fixed* below.

## The gaps

| gap | chapter | status |
| --- | --- | --- |
| XID negotiation | 3.6.1, 6 | done (F1) |
| SREJ (selective reject) | 3.6.4 | done (F2) |
| TEST | 4.3.3.8 | done (F3) |
| UI polled (`UI` + P) | 4.3.3.6 | done (F4) |
| mod-128 bugs found on the way | - | done (B1, B3, B5) |

## Shipped so far

### B1 - poll/final bit lost on modulo-128 links

`lapb_input()` read the poll bit from the second control octet as `0x01`
(the `PF_EAX25` encoding).  Everything downstream compares against `PF`
(`0x10`), so on a modulo-128 link the bit was silently dropped in every
response built as `cmd|pf`.  It is now normalized (`lapb.c`, after the
`controlx` parse): `PF_EAX25` is converted to `PF`, and `sendctl()`
already maps it back when the S frame has to carry it in the second octet.

### B3 - disconnect answer carried a poll bit that was not ours

When an incoming SABM found no listener and the connect went on to the
original caller of a `listen`-flagged port, the refusal was sent as
`DM|PF`.  Whether the incoming leg has an outstanding poll to satisfy is
not known at that point, so the final bit was dropped (`sendctl(...DM)`,
`lapb.c`).  The sibling paths in `lapbtime.c` that emit DMs of their own
get the same treatment.

### B5 - modulo-128 resequence buffer off by one

`lapb.c` scans `reseq[EMMASK+1]` (127 entries).  A loop that consulted the
buffer used `< EMMASK`, which stops one frame early; one more slot is now
walked (`ax25subr.c`).  This one mattered: it is the loop that releases
reordered frames once the missing one that made them reorder has arrived.

### F3 - TEST answered

`TEST 0xe3` is a real frame type and a real command: the receiver must
copy the information field back, copy the P/F bit, and change no state
(4.3.3.8).  It may arrive in *any* link state, so it is answered in
`lapb_input()` right after the DAMA accounting and clear of the per-state
dispatch, which would otherwise not know the type - a response TEST is the
echo of one we sent and is reported here, where the `ax25 test` command
listens.  `ax25 test [<port>:]<call> [via <digi>...] [< <mycall>] [--len
<n>]` builds the polled TEST frame by hand - `axsend()` would re-route it
and lose the parsed `via` path - and prints the answer size.

### F4 - UI polled answered

`UI` with P is not just a datagram anymore.  When we are the challenged
station, the answer is §4.3.3.6: a `DM` (only bit set, from a station in
information transfer `DM|PF`, from a link station in any other state) or a
`RR`/`RNR|PF` when the link is up.  In `ax_recv()`, answered for unicast
only after the interface's `FRF_UI` gate, before the PID switch.  A
blocked port stays silent; a multicast never answers.

### F2 - SREJ

Shipped on both sides, mod-agnostic (the S frame is one octet on
modulo-8, two on modulo-128; the code paths for both are in place):

* Sending a gap report: `resequence()` and `lapb_ack_now()` emit `SREJ`
  instead of `REJ` when the peer is known to handle it.  One outstanding
  report per gap, guarded by `rejsent` exactly as before.
* Taking a retransmission request: `case SREJ` in both the CONNECTED and
  the RECOVERY switches, running `ackours(nr,0)` (everything before N(R)
  is now acked) and then `srej_answer()`: a duplicate of the head of
  `txq` - the frame numbered N(R) - is put on the wire with its original
  sequence number while `vs`/`unack` stay untouched, so the frame remains
  in `txq` until his ordinary ack frees it and nothing behind it is
  repainted.  Terse per the letter of 3.6.4 ("retransmit the single
  I-frame numbered N(R) and shall not retransmit any other").  A repeated
  or stale SREJ is a no-op - a guard checks the requested frame is still
  the oldest outstanding one.

### F1 - XID

Shipped as the one missing level-protocol piece, both sides, together with
the three-valued route memory that makes the probe affordable:

* Knob `ifconfig <iface> ax25-v2.2 off|accept|initiate|always`, default
  **accept**.  `off` is the full switch: the port neither sends an XID nor
  answers one, so a prober hears silence and falls back to SABM, exactly as
  against a plain AX.25 2.0 station.  `accept` answers, does not ask.
  `initiate` is the old `caller` (name taken, no alias) and additionally
  probes on connect - once, per peer, before the SABM.  `always` enforces;
  there, refusal to negotiate ends the connect attempt.
* The probe is a polled XID *command* (one per unknown peer) whose answer
  - or whose silence, bounded by one T1 time-out - is the proof.  The
  initiation is independent of the modulus and changes no modulus: on a
  link a XID speaks capability, not connection parameters, so mod-8 and
  mod-128 peers are probed identically.
* **The answer is honored, the probe forces nothing** (measured
  2026-09-25).  Forcing would mean imposing parameters on the peer; using
  them is the other half of the coin: the largest common denominator the
  answer allows is ours to work with, because the most efficient link is
  the one both ends agreed on.  Today exactly one parameter is taken -
  the modulus, the only one whose mismatch is visible on the wire.  An
  answer offering modulo-128 turns the SABM that follows into a SABME,
  and it does so at `eax25 accept` as well: accept does not *start* a
  negotiation (a SABME against a peer that cannot follow is an unanswered
  frame plus a wait), but a XID that proves the capability has already
  paid for that wait.  Hence **accept-or-XID**.  A port that wants
  neither modulo-128 nor a XID says so twice over, with
  `eax25 off` (nothing is read) or `ax25-v2.2 off` (no XID is sent, so
  there is no answer to read).  N1 and k arrive in the same field and
  are parsed and clamped to **for this one link** (`ax25_apply_peer_xid`:
  the peer's PI=6 N1 in bits becomes a `paclen` ceiling, its PI=8 k a
  ceiling on `ax25_maxframe()`).  They are ours to clamp to, and no
  monitor can see whether we did - which is also why they are *not*
  remembered per route (see the next point).
* Not done, and deliberately: the offered modulus is **not** remembered
  per route.  A XID seen through a nexthop says nothing about the
  nexthop - it may digipeat (mode 2) or forward transparently (mode 1),
  and then the frame is the *destination's* XID, with the destination's
  N1, k and capabilities.  A per-nexthop verdict would therefore be
  wrong for the next destination down that path.  Only a negotiation we
  held with the nexthop itself would prove anything about it, and
  correcting every via-path afterwards is a piece of work of its own -
  a wish-list item, lowest priority.
* The XID information field (PI 3 = HDLC optional functions: the SREJ bit,
  the modulo bits, and bit 22 the segmenter/reassembler; PI 5/6 I-field
  length Tx/Rx N1; PI 7/8 window Tx/Rx k; PI 9 T1) is parsed from the wire
  and echoed back into our answer - answering an XID is not bound to the
  knob.
  Bit 22 is **not** unconditional: it is advertised only when the port
  actually segments.  The effective setting is `ifp->segmentation`, or the
  node's `Ax25_segmentation` when the port says 0 (see `ax25.h`,
  `iface.h`), and it is advertised unless that is `AXSEG_OFF`.  `on` and
  `exempt-l3` both advertise - the *processing* of the received segments
  happens regardless, and `exempt-l3` merely spares `PID_NO_L3`
  (plain text), which is no reason to withhold the capability.  A port
  that is `off` must not invite segments it will not reassemble
  (`xid.c`, `xid_our_info()`; scenario 19).
* What a peer *really* follows is remembered **per route**
  (`struct ax_route`, new field `xid`: UNKNOWN/YES/NO, deliberately not
  persisted - a restart is exactly the moment to ask again).  Learning is
  three-valued exactly like `eax25`, two shapes of proof, and the verdict
  never walks to another path:

#### What the verdict is used for - the two-step rule, FIXED

The learned `xid` is not a licence to reinterpret everything at once.
  Two shapes of proof exist (formal: XID answer; factual: SREJ seen on the
  wire), but the *consequences* split by which one we have:

1. **A peer that is not proven AX.25-2.2** (`xid != YES`) keeps today's
   wire exactly as it was before F1 - the `DM` answer to an offered SABME
   we cannot follow stays `DM` (that is what has proven itself on the
   radio), and no probing of the ambiguous kind is started against him.
   The one thing F1 adds here is the *single settled verdict*: a peer
   whose one probe went unheard is remembered NO so that the very next
   connect does not pay the probe again.
2. **A peer proven 2.2** (`xid == YES`) is answered per the letter - the
   discussion about UA/DM obligations belongs there and nowhere else.
   A `UA` has one more meaning to disambiguate than a `DM` ("answer to
   my SABM" vs "answer to my DISC"); for such a peer we may follow the
   letter, because he gives us the XID that makes the interpretation
   unambiguous.  The same proof carries the *outgoing* consequence, and
   it is the only one that changes what we put on the air: if the answer
   offers modulo-128, the link we open right after the probe runs
   modulo-128, at any `eax25` setting but `off`.  Nothing else follows
   from it - the parameters that would need clamping (N1, k) are read
   and kept, not acted upon, so this step stays one parameter wide.

3. **A peer proven to speak modulo-128** (`eax25 == YES`, the E in
   `ax25 route list`) is asked in modulo-128 on the next connect, at any
   `eax25` setting but `off` - including `accept`, which until now never
   sent a SABME of its own.  The proof is ours and not a report: his SABME,
   or his UA to ours, on this very path.  So the second connect to a 2.2
   station costs one SABME and no question (Thomas, 2026-09-25, from the
   two-node rig: 13 s and a plain SABM on the second connect, because the
   route said YES and nobody looked at it).
   Both verdicts die with the path: `axroute_add()` clears them as soon as
   the port or the digi chain of the entry moves.  A verdict is a statement
   about *a* route, not about a callsign - Z behind C can be reached
   mod-128 because C answers, and the same Z behind D, a plain digipeater,
   cannot be, whatever was learned about him yesterday.  So does the E.

The concrete, already-shipped consequence: every verdict is a *fact seen on
  the wire*, and nothing we ever *assume* is allowed past the gate.  This is
  why the gate stays where it is and the wire does not change for a station
  that has not proven itself.

  The two facts are not interchangeable, and the field remembers only one of
  them.  `xid == YES` means **he answers our XID**, so only a XID *answer*
  writes it.  A XID that merely *arrives* is the other half of an exchange
  and tells us nothing about how he would answer - Thomas, 2026-09-25, from
  the two-node rig: the station asked, we answered, and afterwards it was
  still treated as someone we know nothing about, which is correct.  A
  received *SREJ* is a proof of a different thing: it says he speaks 2.2, and
  it says so for **this session**, so it sets `axp->proto = V2_2` (with a
  XID answer, the only other thing that does) and not a per-route verdict.  A
  route entry may outlive any session; `srej_ok()` may not.

### F1b - the second leg asks for itself

A relayed call arrives as a SABM from A that the digipeater has to follow
with one of its own towards C.  The digipeat branch used to assemble that
SABM by hand - modulus decided, frame sent, T1 started - which is exactly
what `est_link()` does everywhere else, minus the part where a station that
speaks 2.2 gets *asked* first.  It now calls `est_link(peer)`, and that
brings three things with it:

* **The probe is ours.**  It leaves as B->C, source B, on the leg's own path
  (`xid_leg_open()`), so C's answer comes back to us.  As a question in A's
  name it would be a frame that asks A a question C is meant to answer - the
  mirror image of the one that Point D refuses to pass on.
* **It is a question like any other, so the knob decides.**  `ax25-v2.2 off`
  means *we ask nothing*; the leg beyond is then opened with a plain SABM, as
  it always was.  `always` refuses the leg rather than run it unnegotiated.
* **Silence costs the wait, and nothing else.**  On a time-out the leg opens
  with the SABM the wait was for.  No frame is ever written in C's name: a
  station we have not heard is never written about, and A has a timer of its
  own to say so with.

What came out of the wire while this was being built:

* The answer was addressed to **us**, so it found no link and one was made
  for it - a block nobody ordered, which then sat in the table and made
  `ax_answers_to()` take C for our own station on that port.  A block created
  to carry that answer is now taken away again (`made_here`); a block that
  was already there is left alone.  Point D had been doing this all along.
* The job points at the leg's block, and `del_ax25()` frees it.  The owner
  drops the job (`xid_leg_drop()`, called from `del_ax25()` while the pointer
  is still valid) - otherwise a timer callback would carry the address of
  freed memory.
* The job's timer needs a duration set, or `start_timer()` starts nothing and
  the leg waits for itself forever.
* **One question for N waiters.**  `xid_leg_find()` matches the port as well
  as the callsign - C can be reachable two ways, and an answer on one of them
  says nothing about the other - and an answer works off *every* job waiting
  on that question, not the first one found.  A, A-1 and Y wanting the same
  unknown C at the same moment cost one probe and learn the same thing.
* The **immediate answer needs no code**: it is the route entry.  A C already
  proven has no job, no timer and no probe, because `est_link()` never gets
  as far as asking.

### The two corners that shaped the rule

1. A route cannot hold two paths to one callsign at the same time.  A
   station genuinely reachable on both ports keeps pulling the route
   back and forth, and each pull would start a fresh probe.  That is
   *honest* - one value cannot describe two paths - but it is also the
   one case where the old NO would have been more convenient.  Accepted
   as the price of correctness.
2. The reset rides the actual move and not the `AXROUTE_PIN` case:
   a bridged pair of ports pinned by the brass-route guard is *one*
   segment, the station did not move, and the cache must survive.
### What the second leg is, and what it is not

The relayed call exists in two pieces, and they are deliberately not the
same piece:

* The **XID answer** goes to A, in C's name, and is synthesized - after C's
  silence it claims no capability at all (`mod128 = 0`, no SREJ), because
  that is all a station that has not spoken can be said to have proven.
  Answering A in C's name is the only place a frame is ever written in
  someone else's name, and A asked a question about C, so that is what the
  question was for.
* The **connection** is never written in C's name.  The leg carries **A's
  source address**, so C's `UA` reaches A and A's timer - not B - is what
  reports a C that does not answer.  The digipeat relays the call; it does
  not impersonate the station behind it.

This is the *transparent relay* (R+ / digipeat mode 2 with a terminating
LAPB leg), and it is now the behaviour the matrix pins down (scenario 2: a
silent C leaves A with a `SABM` and no `UA` at all).  The alternative - a
*terminating* digipeat that answers A itself in C's name and holds the
call until it drops - is a different design with different consequences for
call signing and for retries, and it is **not** implemented.  It is
recorded here so nobody reads the transparent behaviour as an accident.

### The route file, and what a dead line in it may not do

The route file (`axroute_data`, `ax25file.c`) is a cache, and a cache
with a stale entry in it is a normal thing - a node that was rebuilt with
one port fewer is the ordinary cause.  Three rules, and the second one is
the one that is easy to get wrong:

1. **A route whose port this node does not have is dropped, and said so.**
   The entry names the port it was learned on; if that port is gone, the
   entry would otherwise fall back to the catch-all (`Axroute_default_ifp`)
   behind the operator's back.  The load says which callsign and which port
   it was, so the two possible causes - the port is gone, or the config file
   came up without the `attach` - can be told apart.  (`axroute_iflookup()`)
2. **A dropped entry is not allowed to change a path the operator named.**
   `A->T0T via AL1VE` and `A->B via AL1VE,T0T` work exactly as they always
   did: the immediate destination is the first digipeater, the `T0T` entry
   is never consulted, and the frame goes out over the catch-all or over
   AL1VE's own port.  This is the manual detour, and it is the reason dead
   lines can simply be deleted from the file instead of being repaired.
3. **With no entry at all, the catch-all stays the catch-all.**  `A->T0T`
   with nothing learned goes out on the default interface, with no
   digipeater invented for it.

Scenarios 7 to 10 of `testtools/eaxmatrix.py` hold all three down.

Two things found while building them, both of which had been quietly wrong:

* **`ax25 route add` did not write the file.**  `ax25 route del` did
  (`axroute_flush()`), and the comment in `ax25file.c` claimed `add` did
  too "for a learned entry" - but the learned path went through a timer that
  fires after ten minutes, and a permanent entry not at all.  So an entry an
  operator had just set by hand was gone at the next start, with no message.
  `add` now flushes as well, for the same reason `del` does: what you were
  just told is what the next start finds.
* **`-g` (Debug) means the file is not read and not written at all.**
  `axroute_loadfile()` and `axroute_savefile()` return immediately under
  Debug, so a node started with `-g` starts with an empty route table and
  leaves no file behind.  That is deliberate - a debug run should not
  inherit or damage state - and it is also why the routing scenarios need a
  node started *without* `-g` (`rig.node(..., debug=False)`).  A test that
  forgets this cannot see the behaviour at all, and fails for a reason that
  has nothing to do with the code under test.
